## Toolchain: from `.asm` to `.gb`

* We will use RGBDS-live (<https://gbdev.io/rgbds-live/>),
  an online environment that assembles, links, and runs your code as you
  edit it in a web browser:

~~~
main.asm source -> (rgbasm) -> .o -> (rgblink) -> .gb -> (rgbfix) -> run in emulator
~~~

* `rgbasm`: assembler, converts your assembly into machine code
* `rgblink`: linker, combines code sections and resolves addresses
* `rgbfix`: header fixer, makes the ROM valid for real hardware

## Instructions encoding

  * The assembler converts each mnemonic into its binary code ("opcode")
    that will go into the final ROM file.
  * In the [instruction table](https://gbdev.io/gb-opcodes/optables/),
    the top nibble (4 bits) comes from the row, and the bottom nibble
    from the column.
    * Example: `LD C,A` is translated into: `4F`

## Instructions size

  * Instructions with constants need extra bytes:
    * Example: `LD C,15` is translated into: `0E 0F`
    * For 16-bits constants, the low byte comes first:
    * `JP $AABB`  -> `C3 BB AA`
    * `LD HL,$AABB` -> `21 BB AA`
  * Instructions without data: 1 byte = `opcode`. Eg:
    * `and l`
    * `add hl,de`
  * Instructions with 1 byte of data (`ld r,n`, ...): 2 bytes =
    `opcode data`
  * Instructions with 2 bytes of data (`ld hl,nn`, `jp nn` ...):
    3 bytes = `opcode data data`
  * Prefixed instructions (second page) are 2 bytes = `CB opcode`

## Encoding Format (Advanced)

Many SM83 instructions use fields inside the opcode to encode the operation and its operands.

A useful general form is:

~~~
 7 6 5 4 3 2 1 0
+---+-----+-----+
| x |  y  |  z  |
+---+-----+-----+
~~~

The interpretation of the fields depends on the instruction family.

When `x = 1`, the opcode represents:

~~~
LD r[y], r[z]
~~~

Where `r` is the following table:

~~~
B   C   D   E   H   L   [HL] A
000 001 010 011 100 101 110 111
~~~

Thus:

~~~
LD A, B       %01111000 = $78
LD B, A       %01000111 = $47
LD [HL], E    %01110011 = $73
~~~

One exception is `LD [HL],[HL]` that does not exist, that opcode is instead assigned to the
instruction `HALT`, that we do not use in this lab.

Another regular family is represented by `x = 2`:

~~~
alu[y] r[z]
~~~

Where `alu` is the following table:

~~~
ADD ADC SUB SBC AND XOR OR  CP
000 001 010 011 100 101 110 111
~~~

Examples:

~~~
ADD B       %10000000 = $80
XOR A       %10101111 = $AF
CP [HL]     %10111110 = $BE
SBC E       %10011011 = $9B
~~~

So about half of the [instruction table](https://gbdev.io/gb-opcodes/optables/) is very
regular, while the other is more complex.

The rest of the table contains a mixture of loads, increments, decrements, jumps,
calls, returns, stack operations, and miscellaneous instructions.

## Multi-byte Instructions

Not every instruction fits into one byte.

For example, a jump with a 16-bit destination needs an opcode plus two address bytes:

~~~
JP $2468
~~~

The operand bytes are stored low byte first:

~~~
opcode  $68  $24
~~~

The SM83 also has **CB-prefixed instructions**. When the first byte is `$CB`, another
opcode byte follows. The second byte selects operations such as rotates, shifts, `BIT`, `RES`, and `SET`.

Thus instruction size depends on the encoding of the particular instruction.



## Defining constant data

* `DB`: define bytes to be stored in ROM.

~~~asm
DB 1,2,3,4
~~~

* Example:

~~~asm
  ; assume A contains a value between 0 and 15 
  ld hl, myarray
  ld d,0
  ld e,a
  add hl,de
  ld a,[hl]
loop:
  jp loop

myarray:
  DB 10, 100, 213, 133, 7, 82, 48, 130, 35, 123, 182, 155, 0, 218, 243, 45 
~~~

* `DS`: fills space with a repeated byte.

~~~asm
; create 3 bytes: AA, AA, AA
DS 3, $AA
~~~

## Relative jumps

    Mnemonic     Encoding   Description
    ------------ ---------- ------------------------------------------
    jp nn        C3 nn nn   jump to nn, PC=nn
    jp f,nn      xx nn nn   conditional jump if nz,z,nc,c
    jr PC+dd     18 dd      relative jump to nn (PC=PC+8-bit signed)
    jr f,PC+dd   xx dd      conditional relative jump if nz,z,nc,c

  * `jr` is shorter than `jp` (2 bytes vs 3 bytes)
  * The instruction contains a signed offset between -128 and 127
    instead of an absolute address.
  * Example:
    * `18 00`: no jump
    * `18 FE`: infinite self-loop (jump back 2 bytes)
